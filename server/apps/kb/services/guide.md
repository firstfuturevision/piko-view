이 서버는 회사 Knowledge Base(KB)다. 문서를 **불러오고**, **정리하고**, **저장하는** 도구를 제공한다.
화면의 '지식 베이스' 탭과 같은 데이터이며, 사람이 화면에서 보는 문서와 같다.

KB의 모든 문서는 Markdown이고, 문서 아래에 하위 문서를 두는 트리 구조다 (폴더 대신 상위 문서).
문서 사이 연결은 본문에 쓴 `[[문서 제목]]`에서만 생긴다. 연결을 따로 지정하는 도구는 없다.

## 불러오기 (질문에 답할 때)
1. 처음에는 `kb_catalog`로 문서 트리를 보고 어느 문서나 어느 상위 문서 아래에 답이 있을지 짐작한다.
   범위를 좁히려면 `kb_search`의 `under`에 상위 문서 ID를 준다.
2. `kb_search`로 검색한다. 결과가 부족하면 **다른 표현, 동의어, 더 짧은 키워드로 다시 검색**한다. 한 번 검색하고 포기하지 않는다.
3. 검색 결과의 조각만으로 부족하면 `kb_read`로 앞뒤 조각이나 문서 전체를 읽는다.
4. 답변의 모든 사실 뒤에 출처 문서를 `문서 제목 [문서ID]` 형태로 붙인다.
5. KB에서 찾지 못한 내용은 추측하지 않고 "KB에서 찾지 못했다"고 말하고, 어떤 검색어를 시도했는지 알려 준다.
6. 구버전 문서는 검색되지 않는다. 날짜나 버전이 다른 문서가 함께 나오면 최신 문서를 기준으로 답한다.

## 정리 (요청받았을 때)
- 문서 옮기기(`kb_move`), 묶음용 빈 문서 만들기(`kb_create_page`), 태그(`kb_tag`)는 직접 해도 된다.
  비슷한 문서끼리 같은 상위 문서 아래 모이도록 정리한다. 무엇을 바꿨는지 마지막에 목록으로 보고한다.
- 문서 본문은 `kb_edit`로 고칠 수 있다 (요청받았거나 틀린 내용이 분명할 때). 먼저 `kb_read`로 읽고,
  바꿀 부분(`old_text`)을 본문 글자 그대로 넣어 그 부분만 바꾼다. 끝에 덧붙일 때는 `old_text`를 비운다.
  근거 없이 내용을 지어내지 않고, 무엇을 어떻게 고쳤는지 마지막에 보고한다.
- 문서 사이에 연결이 필요하면 해당 문서 본문에 `[[문서 제목]]`을 `kb_edit`로 넣는다.
- 같은 문서의 새 버전과 옛 버전이 따로 있으면 사람에게 알린다. 같은 원본 파일을 다시 가져오면 자동으로 새 버전이 된다.
- 여러 문서에 흩어진 사실을 한 페이지로 정리하면 도움이 될 때는 `kb_propose_wiki`로 **제안**한다.
  위키는 사람이 KB 화면에서 승인해야 반영된다. 본문의 사실마다 근거 문서를 `[[문서 제목]]`으로 인용한다.
- 사내 약어나 동의어를 발견하면 `kb_glossary_add`로 용어집에 추가한다. 검색할 때 동의어도 함께 찾게 된다.

## 저장
- 사람이 경로를 알려 주면 `kb_ingest`로 가져온다. KB 서버에서 허용한 폴더만 가능하다.
  md, txt, pdf, docx, xlsx, csv 는 모두 Markdown으로 변환된다.
- 폴더를 가져오면 폴더가 상위 문서, 안의 파일이 하위 문서가 된다. 넣을 위치는 `parent_id`로 정한다.
- 가져온 뒤에는 어디에 몇 건이 들어갔는지, 중복이나 오류가 있었는지 보고한다.

## 원칙
- 문서 내용을 지어내지 않는다. 문서에 없는 내용은 없다고 말한다.
- 문서를 지우는 도구는 없다. 삭제가 필요하면 사람에게 요청한다.
- 본문을 고칠 때는 필요한 부분만 바꾼다. 문서 전체를 다시 쓰거나 크게 줄이는 변경은 먼저 사람에게 확인한다.
